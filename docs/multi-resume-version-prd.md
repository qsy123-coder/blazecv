# 多份简历与版本历史 PRD（V2 第三期）

> 状态：已实现　｜　关联：`docs/account-sync-prd.md`

## 背景与问题

V2 前每个浏览器只有一份活动简历，云端每个账号也只有一份。求职者通常同时维护「技术岗」「产品岗」「英文版」等多份简历；改坏内容后也无法回到上一版。

## 目标

- 本地支持多份简历：列表、创建、打开、复制、删除、当前简历标记
- 首页点击模板创建**新简历**；继续编辑走「我的简历」或「继续编辑」
- 版本历史：每 10 分钟自动保留一次，最多 20 个；支持手动保存、恢复、删除
- 云端支持多份简历：列表、按 ID 保存、载入、删除，账号间互不冲突
- 保持本地优先：多份简历与版本历史不依赖登录；云端同步可选

## 非目标

- 版本历史云端同步与跨设备恢复
- 云端冲突自动合并 / 协同编辑
- 简历文件夹、标签、排序拖拽
- 版本对比（diff）

## 本地数据模型

IndexedDB `blazecv`，Dexie：

| 表 | 主键/索引 | 说明 |
|---|---|---|
| `resumes` | `id`, `updatedAt` | 每份简历一条，`doc` 为完整 `ResumeDoc` |
| `settings` | `key` | `active-resume` 指向当前简历 |
| `versions` | `++id`, `resumeId`, `savedAt` | 版本快照，按简历隔离 |

- Dexie 版本 2 新增 `versions` 表，旧库自动升级
- 删除简历时同时删除其全部版本
- 复制简历：新 ID、标题加「副本」，不复制历史版本

## 版本策略

- 保存时对比旧记录 `updatedAt`；若距最近版本超过 10 分钟，先为旧内容建快照
- 每次快照后裁剪到最近 20 个
- 手动「保存当前版本」不受时间限制
- 恢复：保留当前简历 ID 与标题来源，用快照 `doc` 覆盖并触发自动保存
- 删除单条版本不可恢复

## 云端数据模型

```sql
user_resumes(
  user_id uuid FK users(id) ON DELETE CASCADE,
  id text,
  title text,
  doc jsonb,
  created_at timestamptz,
  updated_at timestamptz,
  PRIMARY KEY (user_id, id)
)
```

- 复合主键保证不同账号可以使用相同的本地 ID（如 `sample-resume`）
- 旧的单简历表 `resumes` 与过渡表 `cloud_resumes` 只用于一次性迁移，不再写入
- 删除账号不实现；删除云端简历只删该用户记录

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/resumes` | 当前账号云端简历列表（id / title / updatedAt） |
| GET | `/api/resumes/<id>` | 读取单份，校验归属 |
| PUT | `/api/resumes/<id>` | 按用户 + ID upsert |
| DELETE | `/api/resumes/<id>` | 删除单份 |
| GET | `/api/resume` | 兼容接口：最近更新的一份 |
| PUT | `/api/resume` | 兼容接口：按 `doc.id` upsert |

- 未登录 401；文档校验沿用 `parseResumeObject`；上限 1MB
- 列表与单份读取 `no-store`

## 前端流程

### 我的简历（`/resumes` 独立页面）

- 顶部导航：模板 / 我的简历；云端入口与「新建简历」
- 简历卡片：模板缩略图、标题、模板、更新时间、当前标记
- 操作：打开、复制、删除；标题搜索
- 空状态：引导去模板市场
- 底部提示本地存储与 JSON / 云端备份

### 首页

- 导航提供「我的简历」入口；「继续编辑」打开当前简历
- 模板卡片：点击后创建一份空白简历（新 ID）并进入编辑器
- 打开指定简历：`/editor?id=<resumeId>`

### 编辑器

- 标题栏返回模板库
- 「备份 → 历史版本」：保存当前版本、恢复、删除
- 云端面板：保存当前简历到云端、云端列表逐条载入/删除

### 云端载入

- 读取云端文档 → 确认覆盖 → 写入本地 `resumes` → 设为当前 → `reset` 编辑状态
- 同一 ID 覆盖本地同 ID 简历；不同 ID 新增本地记录

## 边界与异常

| 场景 | 行为 |
|---|---|
| 无本地简历 | 编辑器加载示例并保存为活动简历 |
| URL 指定不存在的 id | 回退到活动简历 |
| 删除当前简历 | 当前切换为最近更新的剩余简历；无剩余则清空 active |
| 删除简历 | 同时删除其版本与本地记录；云端副本需另行删除 |
| 版本恢复 | 先确认，覆盖当前内容；恢复本身进入自动保存 |
| 云端 ID 冲突（同账号） | upsert 覆盖 |
| 云端 ID 跨账号 | 复合主键隔离，不冲突 |
| 云端不存在 | 404 / 列表为空提示 |
| 存储配额不足 | 沿用保存失败提示与 JSON 备份引导 |

## 验收标准

- [ ] 首页无简历时不显示列表；创建后显示 1 份并标记当前
- [ ] 点击模板创建新简历（新 ID、空白内容、所选模板）
- [ ] 打开指定简历加载正确内容；「继续编辑」加载当前简历
- [ ] 复制生成新 ID 与「副本」标题；删除同时清理版本
- [ ] 手动保存版本后，修改并恢复可回到保存时内容
- [ ] 自动版本间隔 ≥10 分钟，单简历最多 20 个
- [ ] 云端可保存多份、列出、逐条载入与删除
- [ ] 不同账号使用相同本地 ID 互不影响
- [ ] `npm run verify` 覆盖创建、列表、版本保存/恢复、云端多份

## 测试

`scripts/verify.mjs`：

- 首页 14 个模板卡片、初始无列表、点击创建 → 返回首页出现「我的简历」
- 多页内容下保存版本 → 改标题 → 恢复 → 标题还原
- 云端注册 → 保存当前简历 → 分享/密码 → 载入 → 退出

## 已知限制

- 版本历史只在本机，换设备不同步
- 云端保存为手动操作，没有自动同步与冲突合并
- 云端列表按更新时间排序，不支持自定义排序
